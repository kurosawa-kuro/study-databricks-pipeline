# 実装カタログ

> 本リポジトリの全成果物(Python / scripts / SQL / Makefile target / コンテナ / data / 設定)を横断で引くための参照テーブル。
> 「何がどう動くか」の確定仕様は [01_仕様書.md](01_仕様書.md)。コードは要点抜粋のみ。

---

## 1. Python モジュール(`src/`)

> `src/` 自体を package とする(二段ネスト無し)。

| パス | 役割 | 引数 / 入出力 | entry point | 呼出元 |
|---|---|---|---|---|
| [src/sql_connectivity.py](../src/sql_connectivity.py) | SQL 経路の本体。SQL Warehouse に接続し SQL を実行 | `--mode query\|catalog\|values` / `--sql-file <path>`(`;` 分割で順次実行)/ `--query "<SQL>"` | `databricks-sql-test` | `scripts/databricks_sql_test.sh` |
| [src/volume_uploader.py](../src/volume_uploader.py) | Cloud Run Job 本体。GCS DL → Files API PUT で Volume へ転送 | env: `GCS_BUCKET` / `GCS_OBJECT` / `VOLUME_PATH` / `DATABRICKS_SERVER_HOSTNAME` / `DATABRICKS_FILES_TOKEN`(timeout 300s) | `csv-to-volume` | Cloud Run Job(`cloudrun/Dockerfile` の ENTRYPOINT) |

必須 env は両モジュールとも `require_env()` で検証し、欠落時は exit code 2。

## 2. シェルスクリプト(`scripts/`)

| パス | 役割 | 必須 env / 引数 | 呼出元 make target |
|---|---|---|---|
| [scripts/databricks_sql_test.sh](../scripts/databricks_sql_test.sh) | `PYTHONPATH` 設定後 `python -m src.sql_connectivity "$@"` を実行する wrapper | `.venv` 必須。引数はそのまま委譲 | `sql-*` / `volume-create` / `volume-clean` / `table-*` |
| [scripts/databricks_volume_upload.sh](../scripts/databricks_volume_upload.sh) | curl で Files API `PUT .../fs/files<path>?overwrite=true`。ローカル → Volume 直接 | `DATABRICKS_SERVER_HOSTNAME` / `DATABRICKS_FILES_TOKEN`、引数 `<local-file> <volume-path>` | `volume-upload` |
| [scripts/gcs_upload.sh](../scripts/gcs_upload.sh) | ローカル CSV を `gs://<bucket>/incoming/` へ(`gcloud storage cp`) | `GCS_BUCKET`、引数 `<local-csv> [gcs-object]` | `gcs-upload` |
| [scripts/deploy_cloudrun_job.sh](../scripts/deploy_cloudrun_job.sh) | AR repo 作成 → image build/push → 実行 SA への IAM 付与(冪等) → Cloud Run Job deploy | `GCP_PROJECT` / `GCP_REGION` / `AR_REPO` / `JOB_NAME` / `IMAGE` / `SECRET_NAME` / `DATABRICKS_SERVER_HOSTNAME`、任意 `RUNTIME_SA` / `GCS_BUCKET` | `job-deploy` |
| [scripts/run_cloudrun_job.sh](../scripts/run_cloudrun_job.sh) | `gcloud run jobs execute --wait`。実行ごとに対象 object / volume path を env override | `GCP_PROJECT` / `GCP_REGION` / `JOB_NAME` / `GCS_BUCKET`、引数 `<gcs-object> [volume-path]` | `job-run` |

`deploy_cloudrun_job.sh` の IAM 付与は実行 SA に `secretmanager.secretAccessor`(secret)と `storage.objectViewer`(bucket)を冪等付与。`--set-secrets=DATABRICKS_FILES_TOKEN=<secret>:latest` で PAT を mount。

## 3. SQL カタログ(`databricks/sql/`)

実行される SQL は全てここ。`--mode values` の SQL は `src/sql_connectivity.py` の `DEFAULT_VALUES_STATEMENTS` にも **二重定義**(`foundation/03_values_seed.sql` と同内容)— 変更時は両方を直す。

### foundation/

| パス | 目的 | 対象オブジェクト | 冪等性 |
|---|---|---|---|
| [01_connectivity.sql](../databricks/sql/foundation/01_connectivity.sql) | 疎通確認 `SELECT 1 AS ok` | — | 読取のみ |
| [02_catalog.sql](../databricks/sql/foundation/02_catalog.sql) | `current_catalog()` → `workspace` 確認 | — | 読取のみ |
| [03_values_seed.sql](../databricks/sql/foundation/03_values_seed.sql) | VALUES で customers/orders を seed + 集計 SELECT | `customers` / `orders` | `CREATE OR REPLACE` + `INSERT OVERWRITE` で毎回再構築 |

### volume/

| パス | 目的 | 対象オブジェクト | 冪等性 |
|---|---|---|---|
| [01_create_managed_volume.sql](../databricks/sql/volume/01_create_managed_volume.sql) | Managed Volume 作成 + `SHOW VOLUMES` | `raw_csv` | `IF NOT EXISTS` |
| [02_drop_volume_artifacts.sql](../databricks/sql/volume/02_drop_volume_artifacts.sql) | table と volume を drop | `customers` / `raw_csv` | `IF EXISTS` |

### table/

| パス | 目的 | 対象オブジェクト | 冪等性 |
|---|---|---|---|
| [01_create_target_table.sql](../databricks/sql/table/01_create_target_table.sql) | ターゲットテーブル作成 + `SHOW TABLES` | `customers` | `IF NOT EXISTS` |
| [02_copy_into_from_volume.sql](../databricks/sql/table/02_copy_into_from_volume.sql) | Volume CSV を customers へ COPY INTO(明示 CAST、`header=true`) | `customers` ← `raw_csv/customers.csv` | **冪等**(取込済みファイル skip) |
| [03_verify_table.sql](../databricks/sql/table/03_verify_table.sql) | 全件 SELECT + `COUNT(*) AS row_count` | `customers` | 読取のみ |

## 4. Makefile target

`make help` に一覧あり。Databricks 系は `doppler run --` 前置が必須(secret 注入)。GCP 系は `gcloud auth` 下で実行(doppler 不要)。

| target | 経路 | doppler | 役割 | 主な引数 |
|---|---|---|---|---|
| `install` | — | 不要 | `.venv` 作成 + `pip install -e .` | — |
| `sql-test` | SQL | 必要 | `SELECT 1`(疎通) | — |
| `sql-catalog` | SQL | 必要 | `current_catalog()` → workspace | — |
| `sql-values` | SQL | 必要 | customers/orders を VALUES から作成 | — |
| `sql-query` | SQL | 必要 | 任意 SQL 実行 | `QUERY="..."` |
| `volume-create` | SQL | 必要 | Managed Volume `raw_csv` 作成 | — |
| `volume-upload` | Files API | 必要 | ローカル → Volume 直接(Phase 1) | `LOCAL_FILE=` `VOLUME_PATH=` |
| `volume-clean` | SQL | 必要 | table / volume を drop | — |
| `table-create` | SQL | 必要 | `customers` テーブル作成 | — |
| `table-copy` | SQL | 必要 | COPY INTO(冪等) | — |
| `table-verify` | SQL | 必要 | row_count / sample 確認 | — |
| `gcs-bucket-create` | GCP | 不要 | GCS バケット作成(冪等) | — |
| `gcs-upload` | GCP | 不要 | ローカル CSV → `gs://.../incoming/` | `CSV=` |
| `secret-create` | GCP | 必要 | PAT を Secret Manager へ登録 | (token は doppler 注入) |
| `job-deploy` | GCP | 不要 | image build/push + Cloud Run Job deploy | (env で上書き可) |
| `job-run` | GCP | 不要 | Cloud Run Job 実行(GCS → Volume) | `OBJECT=` |
| `clean` | GCP+SQL | 不要 | `volume-clean` + Job / secret 削除 | — |

## 5. コンテナ / インフラ

| パス | 役割 | 要点 |
|---|---|---|
| [cloudrun/Dockerfile](../cloudrun/Dockerfile) | Cloud Run Job `csv-to-volume` のイメージ | `python:3.12-slim`。依存(`google-cloud-storage` / `requests`)を先に入れてレイヤキャッシュ。COPY 対象は `src/__init__.py` と `src/volume_uploader.py` のみ。`ENTRYPOINT ["python","-m","src.volume_uploader"]` |

build context は repo root、Dockerfile は `cloudrun/`(`deploy_cloudrun_job.sh` が `-f cloudrun/Dockerfile ... <root>`)。Terraform / docker-compose は無し(GCP リソースは gcloud CLI で管理)。
