# 作業計画書: GCS → Cloud Run Jobs → Databricks Managed Volume → Table パイプライン

## 1. 背景と目的

前身の [`study-databricks-import`](../../study-databricks-import/) は **Databricks Free Edition 内で閉じた** 学習リポジトリで、以下の standalone pipeline を実装済み:

```
SQL Warehouse 接続 → Managed Volume 作成 → Files API でローカルから upload → read_files() → MATERIALIZED VIEW
```

そこでは GCS / Cloud Run 連携は技術的債務として「後回し」と明記されていた([import の 03_technical_debt.md](../../study-databricks-import/docs/03_technical_debt.md))。

本リポジトリ `study-databricks-pipeline` は、その債務を解消し、**ローカル CSV を GCP 経由で Databricks の実テーブルへ取り込む** パイプラインへ拡張する後継プロジェクト。最終形のデータフローは:

```
ローカル CSV → GCS → Cloud Run Jobs → Databricks Managed Volume → Databricks Table
```

import からの主な変更点:

- 入力フォーマットを **JSON → CSV** に変更。
- 前段に **GCS + Cloud Run Jobs** を追加(ローカルから直接 Volume へ上げず、GCS を経由)。
- 最終段を **MATERIALIZED VIEW → 実テーブル (COPY INTO)** に変更。

## 2. アーキテクチャと全体フロー

```text
ローカル CSV  (data/*.csv)
   │  make gcs-upload  (gcloud storage cp)
   ▼
GCS  gs://<bucket>/incoming/*.csv
   │  Cloud Run Job "csv-to-volume"
   │    1. google-cloud-storage で GCS から DL
   │    2. Databricks Files API (PUT /api/2.0/fs/files) で upload
   ▼
Databricks Managed Volume  /Volumes/workspace/default/raw_csv/*.csv
   │  COPY INTO  (SQL Warehouse 経由)
   ▼
Databricks Table  workspace.default.customers
```

ローカルから実行する SQL 系操作は import 同様 `databricks-sql-connector` 経由(`doppler run -- make ...`)。GCS への配置と Cloud Run Job のデプロイ/実行は `gcloud` 経由。

## 3. Free Edition 制約と対処

| 制約 | 内容 | 本設計での対処 |
|---|---|---|
| external location 不可 | Free Edition は GCS を external location / external volume として直接マウントできない | **Cloud Run Job を転送エージェント** とし、`GCS から DL → Files API で Managed Volume へ PUT` する。GCS と Databricks を直結せず、Cloud Run が橋渡しする |
| catalog 固定 | `current_catalog()` は常に `workspace` | テーブル/Volume は `workspace.default.*` 固定で設計 |
| Databricks Connect 不可 | クラスタ直結は使えない | SQL Warehouse + databricks-sql-connector / Files API のみ使用 |

> この「Cloud Run 転送エージェント方式」が本パイプラインの肝。import の [`scripts/databricks_volume_upload.sh`](../../study-databricks-import/scripts/databricks_volume_upload.sh)(curl PUT)で実証済みのパスを Python 化して Cloud Run に載せるだけで、Free Edition の制約に正面から沿える。

技術的補足:

- **Files API**: 単一 PUT は最大 5GB。学習用 CSV では問題なし。
- **COPY INTO**: `COPY INTO <table> FROM '/Volumes/...' FILEFORMAT = CSV FORMAT_OPTIONS('header'='true', 'inferSchema'='true')`。COPY INTO は処理済みファイルを記録するため **再実行で重複行を作らない(冪等)**。Free Edition の managed table で動作する。

## 6. コンポーネント詳細

### GCS

- バケット: `gs://mlops-dev-a-databricks-pipeline`(命名は仮)。region `asia-northeast1`。
- プレフィックス: `incoming/` に CSV を配置。
- 作成: `gcloud storage buckets create`(`make gcs-bucket-create`、初回のみ)。

### Cloud Run Job(`csv-to-volume`)

- 入力 env: `GCS_BUCKET` / `GCS_OBJECT` / `VOLUME_PATH` / `DATABRICKS_SERVER_HOSTNAME`。
- 処理: `google-cloud-storage` で `gs://$GCS_BUCKET/$GCS_OBJECT` を DL → Files API `PUT /api/2.0/fs/files{VOLUME_PATH}?overwrite=true` へ upload。
- PAT: Secret Manager `databricks-pat`(sql+files scope)を `DATABRICKS_FILES_TOKEN` として mount。
- SA 権限: `roles/storage.objectViewer` + `roles/secretmanager.secretAccessor`。
- image: Artifact Registry に push。Service ではなく **Jobs**(バッチ実行のため)。

### 取込 SQL(`databricks/sql/table/`)

1. `01_create_target_table.sql` — 明示スキーマで `CREATE TABLE workspace.default.customers (...)`。
2. `02_copy_into_from_volume.sql` — `COPY INTO ... FROM '/Volumes/workspace/default/raw_csv/customers.csv' FILEFORMAT = CSV FORMAT_OPTIONS('header'='true', 'inferSchema'='true')`。
3. `03_verify_table.sql` — `SELECT count(*)` とサンプル行。

## 7. Makefile target 設計(主導線)

```bash
make install                              # .venv + pip install -e .  (doppler 不要)

# ── GCS 経路(gcloud)──
make gcs-bucket-create                    # バケット作成(初回のみ)
make gcs-upload CSV=./data/customers.csv  # ローカル → GCS

# ── Cloud Run 経路(gcloud)──
make secret-create                        # Secret Manager に PAT 登録(初回のみ)
make job-deploy                           # image build/push + Cloud Run Job deploy
make job-run CSV=customers.csv            # Job 実行: GCS → Volume

# ── Databricks 経路(doppler run -- 前置)──
doppler run -- make volume-create         # Managed Volume raw_csv 作成
doppler run -- make table-create          # CREATE TABLE
doppler run -- make table-copy            # COPY INTO(冪等)
doppler run -- make table-verify          # 行数/サンプル確認

make clean                                # table/volume/job/secret の後片付け
```

ローカル SQL 系は従来通り `doppler run -- make ...` を前置(secret 注入)。GCS / Cloud Run 系は `gcloud` 認証下で実行。

## 9. 検証手順(将来の実装後の e2e テスト)

```bash
gcloud config set project mlops-dev-a

# GCS
make gcs-bucket-create
make gcs-upload CSV=./data/customers.csv
gcloud storage ls gs://mlops-dev-a-databricks-pipeline/incoming/   # 配置確認

# Cloud Run
make secret-create
make job-deploy
make job-run CSV=customers.csv
# Databricks 側で LIST '/Volumes/workspace/default/raw_csv/' を確認

# Databricks Table
doppler run -- make volume-create
doppler run -- make table-create
doppler run -- make table-copy
doppler run -- make table-verify    # row_count = 3 (customers.csv)

# 冪等性
doppler run -- make table-copy      # 再実行で行数が増えないことを確認
doppler run -- make table-verify    # row_count = 3 のまま
```

成功条件:

- `gcloud storage ls` で GCS への配置が見える。
- Cloud Run Job 実行後、Managed Volume に CSV が存在する。
- `table-verify` で row_count = 3。
- COPY INTO 再実行で行数が増えない(冪等)。
